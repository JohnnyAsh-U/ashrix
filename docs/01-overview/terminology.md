# Terminology

This glossary defines the terms used consistently throughout Ashrix documentation and codebase.

---

## Core Components

| Term | Definition |
|---|---|
| **Control Plane (CP)** |It manages identity, PKI, policy authoring, session registry, and gateway command-and-control. The CP never sees application payload traffic. |
| **Gateway** | A stateful reverse proxy that runs in the tenant's infrastructure. It terminates user connections, enforces access policy, and forwards authorised requests to the appropriate Connector tunnel. |
| **Connector** | A lightweight outbound-only agent deployed inside the customer network, adjacent to protected applications. It opens a persistent mTLS QUIC connection to its assigned Gateway and proxies traffic to local applications. |
| **Control Stream** | The persistent bidirectional gRPC/mTLS stream from a Gateway to the CP. Used for configuration sync, policy distribution, heartbeats, revocation events, and audit log streaming. |

---

## Identity and Access

| Term | Definition |
|---|---|
| **Identity Provider (IdP)** | An external authentication authority configured by the tenant (e.g., Okta, Azure AD, Google Workspace). Ashrix delegates user authentication to the IdP via OIDC or SAML 2.0. |
| **Authentication** | The process of establishing who or what is connecting. Ashrix authenticates users via the tenant IdP and authenticates components (gateways, connectors) via mTLS certificates. |
| **Authorisation** | The process of determining whether a verified identity is permitted to perform a requested action. Ashrix's Policy Engine evaluates user, group membership, device posture, MFA status. |
| **Enforcement** | The act of preventing access to a resource. The Gateway is the Policy Enforcement Point (PEP); it acts on the authorisation decision. |
| **Session** | A time-bounded, revocable credential that represents an authenticated user's access to a specific application on a specific gateway. Sessions are stored in Redis and are identified by an opaque token. |
| **Session Ticket** | A short-lived (60-second), single-use, opaque credential issued by the CP after authentication. The Gateway redeems it via gRPC to obtain the user's session details, then creates a gateway-local session. |
| **Policy Bundle** | A versioned, signed collection of access rules pushed from the CP to gateways and connectors. Bundles are verified cryptographically before being applied. |
| **Policy Delta** | An incremental update to a policy bundle, containing only the mutations since the last acknowledged version. Used to avoid transmitting the full policy on each change. |
| **Trust Bundle** | A signed set of trusted CA certificates (Root CA + Intermediate CA) distributed to gateways and connectors. Used to verify peer certificates. |

---

## PKI and Cryptography

| Term | Definition |
|---|---|
| **Root CA** | The top-level certificate authority. Private key stored offline, never exported. Used only to sign the Intermediate CA. |
| **Intermediate CA** | The operational certificate authority that signs all gateway and connector identity certificates. |
| **Identity Certificate** | An mTLS client certificate issued by the Intermediate CA, identifying a specific gateway or connector. Contains the node's stable ID in the Subject CN and SAN. |
| **Bundle-Signing Key** | A CP-held ECDSA key pair used to sign all distributed bundles (policy, trust, revocation, rotation commands). The public key is configured in all gateway env. |
| **Possession Proof** | An ECDSA signature over SHA256(csr, node_id, timestamp) using the node's current private key. Required during certificate renewal to prove that the requester controls the private key of the currently issued certificate. |
| **CRL (Certificate Revocation List)** | A list of revoked certificate serial numbers, distributed from CP to gateways via the Control Stream. Gateways check every inbound Connector connection against the in-memory CRL. |
| **mTLS (Mutual TLS)** | A TLS connection in which both sides present and verify certificates. Used for all server-to-server communication in Ashrix. |
| **Break-Glass Endpoint** | A publicly reachable HTTPS endpoint on the CP (`/v1/renew`). Used by gateways and connectors when their identity certificate needs renewal or recovery, and the normal mTLS channel cannot be used. |

## Node Lifecycle

| Term | Definition |
|---|---|
| **Bootstrap Token** | A single-use, short-lived (5-minute TTL), node-bound credential generated by a CP admin and delivered out-of-band to a new gateway or connector. Used to initiate the first enrollment with the CP. |
| **Enrollment** | The initial process by which a new node (gateway or connector) presents a bootstrap token and a CSR, receives its identity certificate and trust bundle, and persists them to disk. |
| **Renewal** | The automated process by which a node replaces its expiring certificate (at day 60 of a 90-day cert) without interrupting service. Requires a possession proof. |
| **Recovery** | The out-of-band process by which a node with an **expired** certificate re-establishes its identity directly with the CP break-glass endpoint, bypassing the gateway. |
| **Hot Reload** | Replacing a certificate in-memory without restarting the process. All Ashrix components support hot reload for certificate rotation. |

## Networking

| Term | Definition |
|---|---|
| **QUIC** | A transport protocol built on UDP, providing multiplexed streams, built-in encryption (TLS 1.3), and connection migration. Used for the Connector-to-Gateway data plane tunnel. |
| **gRPC** | A high-performance RPC framework using HTTP/2 and Protocol Buffers. Used for all management-plane communication (CP ↔ Gateway, Gateway ↔ Connector management stream). |
| **ALPN (Application-Layer Protocol Negotiation)** | A TLS extension used to signal the application protocol during handshake. Ashrix QUIC connections use ALPN `ashrix-quic-v1`. |
| **0-RTT** | A QUIC/TLS 1.3 feature allowing data to be sent in the first round trip. Disabled in Ashrix due to replay-attack risk. |

---

## Multi-Tenancy

| Term | Definition |
|---|---|
| **Tenant** | An organisation (or individual user) with its own isolated set of applications, policies, gateways, and sessions in the Ashrix platform. |
| **`tenant_id`** | A stable UUID assigned at tenant creation. Present as a namespace key in all CP database tables, Redis keys, and certificate attributes. |
| **`gateway_id`** | A stable identifier for a gateway. Does not change across certificate rotations. |
| **`connector_id`** | A stable identifier for a connector. Does not change across certificate rotations. |

---

## Observability

| Term | Definition |
|---|---|
| **Heartbeat** | A periodic message sent by a gateway or connector to its upstream to confirm it is alive and report operational state (current policy version, cert expiry, state machine position). |
